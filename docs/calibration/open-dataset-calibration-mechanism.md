# 公开数据集校准机制设计（Open-Dataset Calibration Loop）

> 状态：设计稿（v1，2026-09-09）。未经批准不落业务代码。
> 背景：无活体牛场景下，用公开数据集完成「阈值校准 + 管道验证」；真实效果验收仍需活体（NIX-193 / AGENTS.md C6/C7）。

## 1. 机制总览：四层闭环

```
┌─────────────────────────────────────────────────────────────┐
│ ① 数据接入层  data/datasets/<name>/                          │
│    原始数据（.gitignore）+ README 登记（来源/许可/schema/体检）│
├─────────────────────────────────────────────────────────────┤
│ ② 转换导入层  scripts/calibration/import_<name>.py           │
│    数据集格式 → 系统遥测格式 → MANUAL_IMPORT 灌入             │
│    （与真实设备同管道：绑定→快照→分析→告警）                  │
├─────────────────────────────────────────────────────────────┤
│ ③ 校准评估层  scripts/calibration/evaluate_<name>.py         │
│    系统判定结果 vs 数据集标签/文献参数 → 校准报告             │
│    产出：docs/calibration/<date>-<name>-report.md            │
├─────────────────────────────────────────────────────────────┤
│ ④ 反哺层                                                     │
│    a. 参数改动 PR（阈值常量/配置项）→ 部署 → 复评            │
│    b. 数据集切片固化为单测 fixture（小样本进 git）→           │
│       以后任何阈值改动跑回归，防"校准成果被改回去"            │
└─────────────────────────────────────────────────────────────┘
```

## 3. Strathclyde 数据集的利用路径（首条流水线）

1. **体检**（导入前必做）：行数/列结构/采样率/标签分布/加速度量纲 → 写入 README。
2. **转换**：CSV → 系统活动日志格式（activityIndex/stepCount 等价映射，按系统 `activity_logs` schema）；标签作为评估真值保留在旁路文件，不灌库。
3. **灌入**：MANUAL_IMPORT source（与真实设备同代码路径：isCumulativeCounterSource=true 分支、不触发围栏告警、可清理）。目标：test 环境专设 `DATASET-*` 虚拟牲畜 + 虚拟设备绑定，与真实/仿真数据隔离。
4. **评估**：系统活动状态判定（activityStatus：>80 ELEVATED / >40 NORMAL / >20 LOW / else ABNORMAL）与 bolus 标签（反刍/进食 = 低活动段）对比 → 现行阈值的灵敏度/误报率报告 → 反刍/进食行为区分阈值建议。
5. **反哺**：阈值改动 PR + 数据集切片（千行级）固化为 `ActivityThresholdRegressionTest` fixture；文献基线结论（瘤胃 max(0.5×baseline, 1.0) 护栏、体温 <37.5 SENSOR_ABNORMAL）一并进入同一 PR。

## 4. 边界与纪律

- 数据集原始文件永不进 git；仓库只保留 README/schema/小样本 fixture/校准报告。
- 每个数据集必须有许可登记（CC BY 4.0 需署名，引用格式见 README）；无许可确认不下载数据。
- 数据集验证结论标注「文献/数据集校准」，不得表述为真实采集效果（AGENTS.md C6/C7）。
- 灌入数据用独立前缀（DATASET-*）+ MANUAL_IMPORT source + 明确时间窗，验证后清理，恢复设备/牲畜快照（沿用 GPS 压测纪律）。
