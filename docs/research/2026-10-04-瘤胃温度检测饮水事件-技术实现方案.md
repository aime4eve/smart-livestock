## 1. 背景与目标

牲畜饮水时，凉水进入瘤胃导致瘤胃温度快速下降后缓慢回升。基于该"温度谷"形态，可以从 RBC-100 瘤胃胶囊的温度序列中**自动检测饮水事件**，回答"什么时候喝过水、一天喝了几次"。

**业务目标**：

1. 落地官网已宣称、平台未实现的"饮水频次"能力（RBC-100 海外客户询盘待核实项）。
2. 为健康洞察提供新维度：饮水频次骤降是采食量下降/疾病的前导信号（二期可选告警联动）。

**明确不做（文献负结果坐实的能力边界）**：

- ❌ 不承诺估算每次饮水量（升数）——Aubé et al. 2025 证明 RT 曲线参数无法预测事件时长/饮水量。
- ❌ 不承诺日饮水量估算——Cardot et al. 2008 证明需 DMI/产奶量/气温等饲养协变量（R²=0.45）。
- ❌ 不承诺实时告警——固件 30 分钟批量上报带来 ≤30 分钟天然延迟，定位为离线批分析。

## 2. 数据基础（平台已核实）

| 项 | 现状 | 对方案的意义 |
|---|---|---|
| 温度传感器 | RBC-100 STS4x 直测，±0.1°C | 精度远高于信号幅度（2.29±1.82°C），无硬件障碍 |
| 采样节奏 | 固件每 30min 上报周期采 5 个样（实际间隔 6min）；后端 `HealthApplicationService.java:148` 按 5min 间隔展开写入 | 有效分辨率 5~6 分钟/点，全天 ~240 点。**文献 10 分钟级采样已被验证可行（Aubé 2025），我们有 2 倍余量** |
| 存储 | `temperature_logs` 分区表（`PartitionMaintenanceService` 维护），含 `livestock_id`、`device_id`、`temperature`、`baseline_temp`、`delta`（生成列）、`source` | 数据已就位，无需新采集链路；`source` 字段满足多来源治理 |
| 延迟 | 帧批量上报 + 离线补传（固件环形缓冲） | 批分析形态天然匹配；断网时段数据可补齐后回算 |
| 已知口径差 | 后端展开间隔 5min vs 固件实际采样 6min | 系统性时间偏移 ≤4min，对饮水定位（±10min 精度目标）无影响；本方案不改 |

**结论：数据侧零新增硬件/固件改动即可启动。**

## 4. 算法设计（两判据组合检测器）

### 4.1 流水线总览

```
temperature_logs (真实通道)
  → 预处理（按 device 分组）
    → 逐牛逐日基线计算
      → 候选事件检测（判据 A 斜率 ∧ 判据 B 阈值）
        → 形态确认（回升）
          → 事件合并与过滤
            → drinking_events 落库
```

### 4.2 预处理

1. **来源过滤**：仅取 `temperature_logs` 真实通道（`THINGSBOARD` / `AGENTIC_PLATFORM` / `MANUAL_IMPORT` 补传），**排除 `DATAGEN`**（AGENTS.md 红线：仿真数据不得混入真实分析）。
2. **离体过滤**：复用现有体温门卫口径（35–43°C 之外丢弃；固件 <24°C 离体周期不产生有效点）。
3. **发热期与退热期排除（假阳性主源，必须显式处理）**：复用 `FeverAnalysisService` 判级（delta ≥1.0°C 或持续 >2h = FEVER），发热窗口由 `TEMPERATURE_ABNORMAL` 告警的 active/resolved 时间拼装（`AlertBrief` 已带 `createdAt/resolvedAt`，零 DTO 改动）：跳过发热窗口全时段 + **窗口结束后 6h 缓冲**（可标定）。理由：退热期温度从高位回落，谷值落在正常区间，而当日 μ/σ 已被发烧时段抬高，恰恰容易误命中 μ−kσ 判据——这是比发烧期本身更危险的假阳性窗口。发热时段内不产饮水事件，但"发热期间饮水消失/骤减"作为健康信号保留给健康引擎（发烧抑制饮水，反向价值），前端需上下文标注避免误读。
4. **分娩期（存在平台缺口，登记依赖）**：文献确认产犊前 ~15h RRT 下降伴活动增加（Vicentini 2021，即官网"产犊前预警"的依据），与饮水谷形态重叠。**经代码核实：平台分娩预警未实现**（真实告警链路无 calving/parturition 实现，仅 datagen 行为仿真有相关标签），"近分娩期排除"暂无数据源。短期策略：检测层不做硬排除，L2/L3 验证时对成母牛的事件人工核对是否落在产犊窗口并剔除后重算指标；"分娩预警实现"登记为依赖项（答案同步 RBC-100 询盘"待核实"项：未实现）。
5. **类别/生理阶段分层（统计口径，不改算法参数）**：逐牛自适应基线已吸收品种/个体差异（Shirley 2026：个体差异大于群体差异），**检测参数不按品种分档**；但合理频次校验与展示口径必须分层——泌乳牛基准 7.3±2.8 次/日（Cardot 2008）不适用于干奶牛/育成牛/肉牛（肉牛去水槽频次更低、单次量更大，无文献基准，L2 自建）。平台 `Livestock` 已有 `breed`/`gender`/`birthDate`（推月龄）字段支撑分层；泌乳/干奶阶段无字段，列为可选增强不阻塞本期。
6. **去噪**：3 点滑动中值（可选，±0.1°C 传感器精度下通常不必要，标定阶段决定）。

### 4.3 逐牛逐日基线（判据 B 基础）

- 对牲畜 s、日期 d：`μ(s,d) = mean(当日全部有效温度点)`，`σ(s,d) = std(...)`。
- 候选谷值条件：`T_min < μ(s,d) − k·σ(s,d)`，**k = 0.5（T2 标定，2026-10-05 L1 报告，merge-gap=15 口径）**：Aubé 数据集上网格 {0.5,1,2,3,5} 中 F 随 k 单调下降（0.5→0.9400、1→0.9346、2→0.9010、3→0.8317、5→0.4902），k 大导致浅谷漏检；原"k=10 起步（Vázquez-Diosdado 2019）"为 10-min 采样活动判定语境的值，在 5-min 瘤胃温度上不成立，已废弃。配置校验建议对 k>2 告警（k=3 已破 F≥0.90 门禁）。
- 备选基线（若 σ 受污染不稳）：48h 滚动基线温度区间 BTR（Cantor 2018 提出）。

### 4.4 判据 A：下降斜率（FallST，主判据）

- 对相邻有效温度点对 `(T_i, T_{i+1})`（间隔约 5–6min）：
  - `fallRate = (T_i − T_{i+1}) / Δt`（°C/min）
  - 候选条件：`T_i − T_{i+1} ≥ S_th`（绝对步降幅）。
- **S_th = 0.06 °C/min（Δt 归一，T2 标定，merge-gap=15 口径）**：网格 {0.06,0.08,0.10,0.12,0.15} 中 F 随 S_th 单调微降（0.06→0.9400 … 0.15→0.9369），取下限最大化 Se；判据 B（μ−kσ）+ 回升确认保证低斜率阈值下 FP=3/653（PPV 99.5%）。Δt 归一后 6/10-min 重采样 F 相对 5-min 降 0.10pp/1.30pp。等效绝对步降幅：5-min 0.30°C、6-min 0.36°C、10-min 0.60°C（文献自然饮水总降幅 2.29±1.82°C、事件持续 1~2 个采样步）。
- 标定来源：Aubé et al. 2025 开放数据集（**5-min** RT + 视频标注 730 事件，recherche.data.gouv.fr 下载；勘误：本方案初版误记为 10-min）。

### 4.5 形态确认（回升）

- 从谷值起 `T_recoveryWindow = 120 min` 内（Cantor：最冷组恢复 103min），温度回升幅度 ≥ **`R_th = 0.7`×总降幅（T2 标定）**。标定事实：Aubé 数据集（健康牛、无发烧样本）上网格 {0.5,0.6,0.7,0.75,0.8} 差 ≤0.15pp（gap=15 口径：0.5/0.6→0.9408、0.7/0.75→0.9400、0.8→0.9392）——通过判据 A∧B 的候选回升比中位 1.02，R_th 在 L1 近乎不可标定，取 0.7 为防御性默认；其真正作用域是 L2 真实数据的发烧回落段、离体干扰等"降而不回"形态。
- 满足"快降 + 低于逐日阈值 + 自然回升"V 形才确认为事件；只满足幅度不满足回升的，判为发烧/环境干扰丢弃。

### 4.6 事件合并与输出

- 相邻候选事件间隔 **< 15min 合并为一次（T2 标定改定，2026-10-05）**：merge-gap 敏感性扫描（S=0.06/k=0.5/R=0.7，5-min 数据）gap={0,10,15,20,25,30}min 的 F = {82.45, 93.76, **94.00**, 93.90, 93.27, 92.65}——gap=0 时 FP 洪水（211 个）证明合并必须存在；原 30min 系对 Aubé "at least 30 min apart"的误读（该句描述检测分辨下限而非合并规则，论文无合并、拆分由局部峰判据承担），30min 把 Se 压在 86.7% 天花板。15min 下 Se 89.0%/PPV 99.5%/F 94.00（6-min F 93.90）。
- 输出事件记录：`device_id`、`livestock_id`、`event_start_at`（下降起点）、`event_end_at`（谷底，≈饮水结束）、`temp_drop`（降幅）、`min_temp`、`detection_source=RT_ALGORITHM`、`algorithm_version`。
- 时间定位精度目标：±10min（Aubé 已达成 10min，我们采样更密，预期持平或更好）。

### 4.7 伪代码

```
for each (device, day) in temperature_logs:
    points = validPoints(device, day)            # 预处理 4.2
    mu, sigma = baseline(points)                 # 4.3
    candidates = []
    for i in 1..len(points)-1:
        if (points[i-1].t - points[i].t) / dt_min >= S_th  # 判据 A（Δt 归一，S_th 单位 °C/min）
           and points[i].t < mu - k*sigma        # 判据 B
           and recovers(points, i, 120min, R_th):# 4.5
            candidates.append(dip(i))
    events = merge(candidates, minGap=15min)     # 4.6（T2 标定）
    persist(events)
```

## 6. 工程落地设计（映射平台）

### 6.1 数据模型（Flyway 新迁移）

新表 `drinking_events`（量级：每头每日 ~10 行 ×千头 = 日万行级，**普通表 + 索引即可，不进分区表清单**）：

```sql
CREATE TABLE drinking_events (
    id              BIGSERIAL PRIMARY KEY,
    device_id       BIGINT NOT NULL REFERENCES devices(id),
    livestock_id    BIGINT REFERENCES livestock(id),
    event_start_at  TIMESTAMP NOT NULL,     -- 下降起点 ≈ 开始饮水（应用层写 Instant UTC，#17 同向）
    event_end_at    TIMESTAMP NOT NULL,     -- 谷底       ≈ 饮水结束
    temp_drop       NUMERIC(10,2) NOT NULL, -- ≥ 0.5°C 量级（#13 教训：差值列 DECIMAL(10,2) 起）
    min_temp        NUMERIC(10,2) NOT NULL,
    source          VARCHAR(20) NOT NULL,   -- 沿用 temperature_logs 的 source 口径（真实通道 + MANUAL_IMPORT）
    algorithm_version VARCHAR(10) NOT NULL,
    created_at      TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMP NOT NULL DEFAULT NOW(),
    UNIQUE (device_id, event_start_at, algorithm_version)
);
CREATE INDEX idx_drinking_events_livestock_time ON drinking_events (livestock_id, event_start_at DESC);
```

> DDL 对齐仓库惯例（`V20260926100000__epidemic_contact_workbench.sql` 范本）：`TIMESTAMP`（非 TIMESTAMPTZ，Instant 按 UTC 由应用层写）、`REFERENCES` 外键、`updated_at`；source 沿用动态口径不加 CHECK。> 注意与 `PartitionMaintenanceService` 的兼容性说明（AGENTS.md 时序分区约束）：本表不分区，已核实该服务只管 5 张既有表，无冲突。

## 9. 风险与开放问题

1. **S_th 斜率阈值对采样节奏敏感**：L1 标定用 10min 间隔数据，我们是 5~6min——斜率需按 Δt 归一或重标定（L1 实验设计时覆盖两种间隔）。
2. **放牧/肉牛场景无文献基准**：Cardot 基准是自由散栏泌乳牛；肉牛饮水次数分布未知，L2 阶段以自建回放分布校验。
3. **σ 污染与退热假阳性**：当日若有长时间异常（发烧前驱），μ/σ 被抬高/压低——4.2 的发热排除 + 退热 6h 缓冲缓解；备选 BTR 基线。退热缓冲时长（6h）为工程估计值，L2 阶段用真实发烧-退热序列标定。
4. **后端 5min 展开口径**：若未来固件侧提高温度采样率，`HealthApplicationService.java:148` 的展开逻辑需同步，避免双口径（登记为观察项，不在本期修）。
5. **多设备共存**：一牲畜绑定多胶囊时按 device 独立检测、livestock 层去重合并（同一温度谷以降幅大者为准）——待真实设备形态确认。
6. **分娩期无排除数据源（已核实的平台缺口）**：产犊前生理性温度下降（Vicentini 2021）会被检出为"饮水事件"，在分娩预警实现前无法自动剔除——L2/L3 验证人工核对，成母牛场景的准确率指标需注明此残留误差；同时它反向提示：若未来做分娩预警，饮水检测器的事件流可复用为特征源。
