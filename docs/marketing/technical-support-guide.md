## 1. 支持分级与响应约定（内部目标）

| 级别 | 定义 | 典型示例 | 首响目标（内部） | 更新节奏（内部） |
|---|---|---|---|---|
| P1 | 平台不可用、数据安全风险、核心业务大面积中断 | 全站无法登录、租户数据越权、地端服务整体宕机 | ≤1 小时 | 每 2 小时通报直至缓解 |
| P2 | 关键功能受损、批量对象异常 | 告警链路失效、批量设备无遥测、授权进入保护模式 | ≤4 小时（对齐 PREMIUM 承诺） | 每个工作日 ≥1 次 |
| P3 | 单个对象或少数用户异常，有绕过方案 | 单设备离线、单个围栏误报、个别页面报错 | ≤8 小时（对齐 STANDARD 承诺） | 每 2 个工作日 ≥1 次 |
| P4 | 使用咨询、配置调整、非阻塞缺陷 | 功能咨询、报表口径、文档勘误 | ≤2 个工作日 | 处理完成时答复 |

补充规则：

1. 海外客户同时记录客户时区与跟进窗口（对齐 02 手册跨时区协作条款）。
2. 响应时效为内部运行目标，对客户沟通时不引用"内部目标"字样，按订阅档位承诺口径表达。
3. 安全类事件（疑似越权、密钥泄露、入侵迹象）不受分级约束，立即按 02 手册第 10 节升级。

## 2. 支持渠道与工单流转

### 2.1 渠道

| 渠道 | 用途 | 说明 |
|---|---|---|
| 工单系统 | 对外统一受理入口 | 所有问题的唯一事实源，邮件 / 会话问题须回填工单 |
| 商务转介 | 销售 / 渠道带来的客户问题 | 商务补全客户与环境信息后转支持，不私下处理 |
| 值班机制 | P1 / P2 覆盖 | 值班表与升级链由支持负责人维护（见 02 手册待确认项） |

### 2.2 工单流转

```
受理（02 手册最低信息清单）→ 定级（P1–P4）→ 定位（四层决策树 / 设备类先走硬件网络层）
→ ├─ 配置 / 数据 / 商务类：处理并答复
   ├─ 疑似缺陷：按第 6 节升级研发（02 手册第 7 节升级单模板）
   └─ 商务类（续费 / 升配 / 合同）：转商务负责人
→ 客户确认结果 → 关闭（满足 02 手册第 1 节关闭标准）
```

流转要点：

1. 授权、订阅、配额类问题先查商业状态再判代码（02 手册 5.6 节）。
2. 支持、商务、研发单一问题单一工单，避免多头回复。
3. "已回复"不等于"已关闭"。

## 3. 常见问题 FAQ

### 3.1 登录失败（提示 token 过期 / 无权限）

- **排查**：确认登录入口与环境正确 → 账号与租户状态（`TENANT_DISABLED`：租户被停用，可由平台管理员恢复）→ 角色权限（`AUTH_FORBIDDEN`）→ 登录标识格式与密码策略（见 3.19）→ 记录业务错误码与 `requestId`。
- **处理**：登录态过期重新登录即可；权限问题对照权限矩阵（`docs/product/customer-journey.md`）核对预期可见范围。
- **升级**：账号状态正常仍无法登录，带 `requestId` 升级。

### 3.2 托管模式开通免费试点授权失败 / 到期日与预期不符

- **机制（2026-10-12 起）**：免费试用为**全平台统一截止时刻**（服务端配置 `smartlivestock.trial.ends-at`，当前为 2027-09-30T21:00Z，即 UTC+3 地区 2027-10-01 00:00），运营侧试点授权与租户自助试用两条路径都收敛到该时刻；配置留空才回退旧的 365 天 / 14 天滚动窗口。客户问"为什么不是 365 天 / 14 天"按此解释，属预期行为。
- **现象 A：开通返回状态冲突**。仅 `ACTIVE`（正式订阅）租户会被拒绝；非 ACTIVE 状态（未订阅 / `TRIAL` / `EXPIRED` / `CANCELLED` / `SUSPENDED` / `RENEWAL_FAILED`）均可重新开通，到期日收敛为统一截止日。ACTIVE 租户的特殊诉求转商务。
- **现象 B：试点授权一开通就显示过期**。核对服务端统一截止时刻配置是否被写成过去时间（曾因年份写错导致全部试用秒过期，dev 冒烟拦截）；属部署层配置问题，升级部署负责人改配置并重启，不要反复给客户重新开通。
- **注意**：该接口仅限平台运营角色，且仅云端托管（HOSTED）模式可用；地端（ONPREM）试点期以离线授权文件为准，到期日由签发方按统一截止日签发。

### 3.3 地端授权导入失败

- **排查顺序**：
  1. 文件完整性：`.sllicense` 是否被改名校验 / 传输损坏（payload 摘要不匹配会被拒）。
  2. 签名与公钥：文件 `keyId` 是否在地端内置公钥列表中（旧公钥轮换后旧文件需重新签发）。
  3. 绑定校验：租户 ID、安装 ID、主机指纹是否与当前环境一致。
  4. 配额校验：当前牲畜 / 围栏 / 牧工 / 设备数是否超过授权配额（超限导入失败，不进入降级或激活）。
- **处理**：按失败原因重新签发授权（配额不足需先降用量或扩大授权配额）。
- **升级**：文件与登记信息一致仍导入失败，收集授权状态页截图与失败错误码升级研发。

### 3.4 主机指纹不匹配（fingerprint 校验失败）

- **原因**：授权签发后客户更换了主机 / 虚拟机迁移 / 硬件变更（网卡、磁盘等影响指纹的组件）。
- **处理**：客户在地端管理页重新获取登记信息（安装 ID + 新主机指纹 + 公钥 ID）→ 提供给签发方重新签发授权 → 导入新文件。旧授权被替换标记，数据不受影响。
- **红线**：不得引导客户绕过指纹校验或修改系统时间"骗过"校验。

### 3.5 时间回拨保护触发（进入保护模式）

- **现象**：地端进入 SUSPENDED 保护状态，原因为 `LICENSE_TIME_ROLLBACK`。
- **原因**：系统检测到当前时间早于历史最大已观测时间（防篡改机制），常见于手工改时间、虚拟机快照回滚、NTP 异常。
- **处理**：校正系统时间（启用可靠 NTP 同步）→ 确认当前授权在有效期内 → 等待周期校验恢复，或导入有效授权恢复。
- **提醒**：虚拟化环境部署时，安装阶段就应确认宿主机时间同步策略，避免快照回滚触发保护。

### 3.6 试点 / 订阅到期后功能变化

- **机制**：到期自动降级为基础免费版（FREE / BASIC），功能按 FeatureGate 收窄（数据保留 7 天、围栏 ≤3、高级健康功能锁定），**数据保留不删除**。
- **处理**：向客户解释降级 ≠ 数据删除；续费走人工合同 + 付款确认，签约后签发正式授权恢复激活状态与档位能力。
- **注意**：地端已过期降级为 FREE 的试用，不能通过重新导入普通试用授权回到试用状态，必须签发正式（ACTIVE）续费授权；云端托管租户在统一截止日（2027-09-30）前可由运营侧重新开通试点授权（见 3.2）。

### 3.7 续费授权导入后状态未恢复

- **排查**：确认拿到的是正式（ACTIVE）类型授权而非试用文件 → 授权在有效期内 → 导入时配额校验是否通过（当前用量超新授权配额会失败）→ 授权状态页查看最近校验结果与错误码。
- **处理**：配额问题按 3.3 处理；签发内容错误（档位 / 到期时间）由签发方重新出文件。

### 3.8 设备遥测不上报

- **先走硬件 / 网络层**（02 手册 4.1–4.2 节）：
  1. 硬件：设备电量与开关机状态、GAT-100 入网与佩戴、RBC-100 投服登记与验活、设备与牲畜绑定关系。
  2. 网络：网关在线与供电、频段匹配、现场 RSSI/SNR、网络服务器是否收到上行帧。
- **再查平台**：批量无数据优先查网关与接入链路；单设备无数据优先查设备本身。
- **升级**：网络层正常但平台无数据，记录设备编号、时间窗、最后转发时间升级。

### 3.9 GPS 轨迹为空（设备有数据）

- **排查顺序**：
  1. 当前选择的牧场（farm scope）是否正确。
  2. 牲畜是否有**有效安装关系**（active installation）。
  3. 查询时间窗是否覆盖数据时间；时间格式是否符合接口约定（URL 编码、时区）；时区设置是否正确（"我的"页可查改，与牧场 → 租户 → 平台时区链共用同一时区列表，影响时间显示与查询口径）。
  4. GPS 入网任务（ingestion task）是否失败或积压。
- **经验**：轨迹为空最常见原因是安装关系失效与时间窗 / 时间格式问题，先排除再怀疑缺陷。

### 3.10 地图底图不对 / 离线瓦片异常

- **先核对瓦片源行为**（2026-10-12 起按**牧场所在国家 / 时区**自动选择，不再跟随查看者客户端时区）：牧场时区为中国时区默认高德底图（GCJ-02 坐标），其他默认 OSM。牧场时区按牧场 → 租户 → 平台链路继承，修改牧场或租户时区会改变瓦片源；客户报"地图变了 / 底图不对"先查牧场与租户时区设置，不当作缺陷处理。
- **排查**：在线模式下底图是否正常（在线异常为瓦片服务问题，离线异常为本地包问题）→ 离线瓦片包是否已下载并覆盖当前牧场区域 → 离线包管理页确认范围与版本。客户端已不再内置示例瓦片包，未下载离线包时弱网下可能无图，属预期行为。
- **处理**：重新下载对应区域离线包；瓦片服务异常升级部署层排查。
- **边界**：离线瓦片包只解决"看地图"；设备无网时数据上传能力仍受网络层限制。**对外材料已不宣传离线作业**（离线围栏 / 牲畜缓存等未上线），支持侧向客户解释时只描述现有离线瓦片包行为，不扩展承诺。

### 3.11 时间显示与预期不符

- **先查时区设置**：界面时间、日 / 小时统计按查看方时区显示（"我的"页设置，与牧场时区链共用同一时区列表）；牧场时区按牧场 → 租户 → 平台三级继承，可在牧场详情单独设置；GPS 质检（QC）页时间统一按操作者本机时区显示（2026-10-16 裁决）。跨时区远程查看（如管理端看海外牧场）显示的是查看方时区，不是牧场当地时间，属预期行为。
- **排查**：时区设置是否被改动 → 对比设备采集原始时间与页面显示时间（差值应恰为时区偏移）→ 服务端按调用方时区参数分桶统计，确认请求参数未被网关改写 → 牧场编辑是否丢失时区（2026-10-12 已修复牧场更新丢时区问题，旧版本客户端先升级）。
- **处理**：引导客户改回正确时区；确认是统计口径歧义的按上述解释；数据本身时间错乱（非偏移量差异）升级研发。

### 3.12 iOS 客户端无法安装 / 提示过期

- **现状（2026-10-16 起）**：iOS 以正式开发者团队签名，经 **TestFlight** 邀请分发（版本显示 0.6.1 (构建号)）；原免费团队 7 天描述文件方式已废止。TestFlight 构建**有效期 90 天**，到期后 App 提示过期属预期行为。Web 登录页的 IPA 下载入口仍保留，仅供登记设备（开发 profile）验证使用。
- **处理**：到期或提示过期 → 在 TestFlight 中更新到最新构建；未收到 TestFlight 邀请 → 核对测试员邮箱是否已加入、邀请是否过期，转运营补发；IPA 直装失败 → 核对设备是否在开发 profile 登记列表中（登记名额有限，不作为客户批量分发方式）。
- **边界**：TestFlight 分发不等于 App Store 上架；客户询及上架节奏转商务，不承诺时间。App 显示名 **BoviScout**（2026-10-21 起随新构建生效，更早的构建显示 Smart Livestock），客户看到两种名字属版本差异，不是两个 App。工单与文档中不记录 Apple 开发者团队 ID、账号与证书文件。

### 3.13 地端备份与恢复

- **流程**：使用发布包自带备份脚本（PostgreSQL 逻辑备份 + 瓦片数据卷 + AI 模型卷 + 配置与证书目录，含校验和）；恢复脚本会先停写入服务、恢复数据、校验授权状态与数据库连接后再启动。
- **恢复后必查**：`/health` 健康检查通过、授权状态页校验结果正常、核心链路（登录 / 地图 / 告警）抽测。
- **要求**：备份由客户按约定周期在本地执行；支持侧提供操作指引，不代操作生产数据。

### 3.14 HTTPS 证书过期

- **现象**：浏览器告警、部分客户端无法访问。
- **处理**：客户更换证书目录下的证书文件（fullchain + 私钥）→ 重启入口服务 → 运行健康检查脚本确认证书检查项通过。
- **预防**：健康检查脚本包含证书有效期检查项，建议纳入客户例行巡检；到期前 30 天主动提醒客户。

### 3.15 Open API 限流 / 调用失败

- **错误码对照**（完整表见 02 手册 5.5 节）：`RATE_LIMIT_EXCEEDED` 超出限流；`AUTH_API_KEY_INVALID` Key 无效 / 吊销；`AUTH_API_KEY_EXPIRED` 过期；`AUTH_FORBIDDEN` scope 不足。
- **排查**：记录 API Key 名称（**不记录完整密钥**）、时间、HTTP 状态、`requestId` → 查调用统计与限流配置（每分钟请求数 + 每日配额）→ 对照合同范围。
- **处理**：限流属正常保护，客户需提升配额的转商务评估；Key 状态问题在门户重新签发。

### 3.16 功能入口不可见 / 显示升级提示

- **排查**：用户角色（是否越权预期）→ 订阅层级与状态（trial / active / free / expired / suspended）→ FeatureGate 类型（LOCK 锁定 / LIMIT 超量 / FILTER 数据裁剪）→ 设备依赖是否满足（如健康评分需 GPS 追踪器 + 瘤胃胶囊）。
- **处理**：属订阅边界的功能引导升配（转商务）；配置错误的修正后验证（02 手册第 6 节）。

### 3.17 手机 App 下载入口异常

- **入口边界**：下载行只在 Flutter Web 登录页显示；已安装的原生 App 内不显示。固定文件路径是 `/downloads/hkt-livestock-latest.apk` 和 `/downloads/hkt-livestock-latest.ipa`，版本信息来自 `/downloads/versions.json`。
- **现象 A：版本号不显示，但 APK / IPA 链接可点**。登录页对版本清单做 best-effort 加载，超时或读取失败不阻塞登录和下载；先按部署层检查 `versions.json` 是否随发布包进入 nginx `/downloads/`，不要把它当登录功能故障。
- **现象 B：下载链接 404 / 文件不存在**。重点查部署层：本次发布包是否包含 `downloads/`，容器内 `/downloads/` 是否有固定名文件。缺构建产物时重新执行 Android / iOS 打包和下载清单 staging，再重建 Web 发布包。
- **现象 B2：IPA 版本陈旧**（2026-10-20 修复）：iOS 打包产物文件名曾变更而 staging 脚本只认旧名，导致下载区 IPA 自 09-30 起未更新；现脚本已兼容新旧两种 IPA 文件名。客户报 IPA 版本落后时先核对 `versions.json` 中 ipa 版本与最新发版号是否一致，再按部署层重新 staging。
- **现象 C：iOS 下载后无法安装 / 启动**。先按 3.12 核对设备是否在开发 profile 登记列表、构建是否过期；TestFlight 用户引导其在 TestFlight 更新，不要用 IPA 覆盖安装。支持侧不把 IPA 下载入口或 TestFlight 说成 App Store 上架。
- **红线**：不引导客户直改 nginx 文件名绕过发布链；版本清单与实际包不一致时按部署层修复。

### 3.18 牲畜 / 地图状态长时间未刷新

- **先看界面证据**：统一 Signal 架构下断线会保留最近一次权威数据并显示 stale / 滞后提示；有 stale 提示时先查客户端网络、登录会话与牧场切换，再查服务端。没有 stale 提示的偶发延迟先确认查看的前端版本是否包含 Signal 更新。
- **再核对传输层**：Web 端优先使用 SSE；浏览器、代理或防火墙阻止 SSE 时会退回 3 秒增量轮询。不要仅因 SSE 不可用就升级，先确认轮询是否恢复、数据是否继续变化。
- **再查服务端链路**：确认设备最新遥测时间、`/signals/livestock` 或 `/signals/map` 响应、对应牧场 revision 是否变化；涉及重复帧时核对平台是否按幂等规则丢弃重复遥测。
- **升级**：客户端网络正常、轮询返回无变化、但业务侧确有新遥测时，升级研发并带时间窗、设备编号、前端版本、API 响应摘要与 `requestId`；禁止修改生产数据强行刷新。

### 3.19 登录提示"标识或密码错误" / 新建用户失败

- **机制（2026-10-14 起）**：登录标识支持账号 / 手机（E.164 国际格式，如 +27…）/ 邮箱三种，系统按格式自动识别；登录失败统一返回泛化错误，不区分"账号不存在"与"密码错误"（安全设计，不是缺陷）。密码策略 ≥8 位且含大小写字母、数字、符号四类；首次登录与运营侧重置后强制改密，强制改密锁定页刷新不丢失（2026-10-19 修复）。
- **排查**：手机号是否带正确国际区号（登录区号选择器按设备时区猜默认区号，可能猜错，让客户确认 +XX）；邮箱 / 账号大小写不敏感但不能带空格；是否处于强制改密未完成状态；旧的"裸手机号"账号仍可按原字串登录（兼容保留）。
- **新建用户失败**：账号 / 手机 / 邮箱至少一个必填且格式合法；重复标识返回明确的重复错误（中英文）；建号对话框已内置确认密码与策略前置校验，失败留在对话框内不丢表单。
- **升级**：标识格式合法、租户与账号状态正常仍无法登录，带 `requestId` 升级。

### 3.20 设备需要跨租户转移 / 入网提示"已被其他租户占用"

- **机制（2026-10-12 / 10-19 起）**：设备 EUI **全球唯一**，跨租户不可重复注册；移交由平台管理员在管理端租户详情页「设备移交」卡片按 EUI 查归属 → 确认移交，服务端事务校验（设备不存在 / 已在目标租户 / 目标租户缺失 / 存在活跃安装关系均拒绝），全程审计留痕。
- **排查**："已被其他租户占用"先用移交卡片「查归属」确认当前归属租户；仍绑在牲畜上（活跃安装关系）的设备必须先在源租户解绑再移交。
- **边界**：移交属平台运营动作，不开放租户自助；设备所有权争议转商务。设备在线率按租户真实计算（2026-10-19 起），租户无设备时显示"—"而非 100%，不是缺陷。

### 3.21 饮水行为数据为空 / 不更新

- **机制**：饮水行为由瘤胃胶囊体温序列每日凌晨批处理推导**前一日**数据，当日没有数据属预期；无瘤胃胶囊或胶囊无有效体温序列的牲畜没有饮水数据；发热及退热后 6 小时窗口内的体温下降被排除、不计为饮水。
- **排查**：胶囊是否在绑且有体温上报（3.8）→ 是否已过凌晨批处理窗口 → 当日是否有活跃体温告警（排除窗）→ 需要时由管理端触发重算。
- **边界**：当前只有行为统计（次数、时刻分布、7 日趋势、30 日基线；同类对比为 Premium），**无饮水异常告警、无饮水量**；客户问准确率一律不给数字（见工具包 FAQ 15）。生理事件手工补录入口在空态也可达，不要把"空态"当故障。

## 4. 四层排查决策树

> 对齐 `AGENTS.md` 故障层定位法：先判断工作单元在哪一层损坏，只修那一层。涉及设备与网络的遥测类问题，先按 02 手册走硬件层 / 网络层（见 3.8），再进入本决策树。

```
客户报告问题
  │
  ├─ 单设备 / 单区域无数据？ → 先走硬件层 / 网络层（02 手册 4.1–4.2）
  │
  ▼
【1. 环境层】是个别用户还是所有用户？
  ├─ 个别：客户网络 / DNS / 防火墙、客户端版本与缓存、
  │        是否误用不同环境入口或账号 → 解决或转下一层
  ▼
【2. 部署层】服务本身是否正常？
  ├─ 检查：/health 健康检查、后端日志、前端发布版本是否包含目标功能、
  │        容器状态、入口路由与配置
  ├─ 典型：API 正常但前端无变化 → 前端未重新构建部署
  │        （Web 端离线 service worker 已禁用并自动注销旧缓存，
  │          部署后浏览器残留旧包问题已消除，仍先核对容器内 main.dart.js）
  ├─ 工具：check-release-health.sh（地端）、容器状态与日志命令
  ▼
【3. 数据层】数据是否存在且范围正确？
  ├─ 检查：牧场归属与租户隔离、farm scope、时间窗与时区、
  │        安装关系、订阅 / 授权 / FeatureGate、数据保留策略、来源 source、
  │        GPS ingestion task 是否积压
  ├─ 典型：轨迹为空（安装关系 / 时间窗）、功能不可见（订阅层级）
  ▼
【4. 代码层】以上全部排除，且有明确复现证据
  └─ 按 02 手册第 7 节升级单格式升级研发
     （复现步骤、requestId、日志片段、已排除项、验收标准）
```

各层检查动作与工具速查：

| 层 | 判断问题 | 检查动作 | 工具 / 依据 |
|---|---|---|---|
| 环境层 | 个别客户异常 | 换网络 / 换设备交叉验证、核对环境入口、客户端版本 | 客户配合测试 |
| 部署层 | 全员异常或功能缺失 | 健康检查、服务与容器状态、前端版本、路由配置 | `check-release-health.sh`、`/health`、容器日志 |
| 数据层 | 数据缺失 / 范围错误 | 租户与牧场归属、时间窗、安装关系、授权与配额、source 标记 | 管理端查询、授权状态页、业务错误码 |
| 代码层 | 可复现且已排除前三层 | 整理升级单 | 02 手册第 7 节模板 |

## 5. ONPREM 远程支持边界

地端环境部署在客户内网，支持过程必须遵守以下边界：

### 5.1 访问边界

1. **不直连客户环境**：我方不持有客户服务器凭据，不索取数据库直连、SSH 凭据或管理员密码。
2. **远程会话需客户授权**：确需远程排查时，通过客户指定的受控远程会话 / 堡垒机进行，客户全程可见，会话结束后客户可审计。
3. **数据不出场原则同样约束支持过程**：客户业务数据（牲畜档案、位置轨迹等）不出客户内网；传输给我方的仅限排障必需的技术信息（错误码、`requestId`、日志片段，需脱敏）。

### 5.2 日志导出流程（客户执行 → 工单回传）

1. 客户在授权管理页导出：当前授权状态、最近校验结果、失败原因截图。
2. 客户运行发布包健康检查脚本，保存输出。
3. 客户按支持指引导出指定时间窗的服务日志（含 `requestId` 的错误片段，不做全量导出）。
4. 客户自查并脱敏（移除凭据、证书、业务数据）后，通过工单上传打包文件。
5. 支持侧在工单内记录文件清单与哈希，保证可追溯。

### 5.3 变更边界

1. 授权类变更（续期、扩容、换机重签）一律通过**重新签发授权文件**完成，客户导入，不支持库内手工修改授权状态。
2. 引导客户执行的命令以发布包脚本与健康检查为准；**禁止让客户执行破坏性 SQL 或绕过业务状态机的操作**（02 手册售后红线）。
3. 版本升级、数据修复等超出脚本能力的变更，升级研发评估后由我方出书面操作方案，客户确认后执行。

## 6. 升级路径（何时升级研发）

### 6.1 必须升级研发的情形

1. 四层排查（环境 / 部署 / 数据）完成且排除，问题仍可复现。
2. 疑似数据错误且涉及共享写入链路（遥测、GPS 入网任务积压不收敛）。
3. 授权校验链路异常：文件与登记信息一致仍导入失败、保护模式无法按文档恢复、到期降级与续费恢复行为与设计不符。
4. 安全类事件（02 手册第 10 节，立即升级，不等排查）。
5. 同类问题短时间内多客户报告（疑似版本缺陷）。

### 6.2 不升级、先自查的情形

1. 客户操作理解偏差、角色权限预期不符（对照权限矩阵）。
2. 订阅 / 授权 / 配额商业状态问题（转商务，见 3.6 / 3.7 / 3.16）。
3. 设备电量、佩戴投服、网关覆盖等硬件网络层问题（02 手册 4.1–4.2）。
4. 文档已覆盖的 FAQ 场景。

### 6.3 升级单要求

按 02 手册第 7 节模板提交，必须包含：复现步骤、环境与版本、时间窗、`requestId`、日志或截图证据、四层（及硬件 / 网络层，如适用）已排除项、验收标准。研发接收以"可复现或有足够证据、影响明确、非代码因素已排除"为准。

## 7. 使用红线（与 02 手册售后红线一致）

1. 不向客户展示完整 API Key、token、数据库连接或内部地址（含内部 IP 段）。
2. 不直接修改生产数据绕过业务状态机或授权状态机。
3. 不把仿真数据（DATAGEN）当作真实设备数据解释。
4. 不承诺未经确认的修复时间；"无法复现"不等于"不是问题"。
5. 响应时效按订阅档位对外口径表达，不泄露内部目标值。
6. 对外不宣传离线作业（离线地图 / 围栏 / 缓存）；不把 TestFlight 或 IPA 下载入口说成 App Store 上架；不在工单与文档中记录 Apple 开发者团队 ID、账号与证书文件。
