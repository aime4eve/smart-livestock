## D. 算法与长期技术运营

**1. 哪些当前的警报/算法在胶囊（bolus）内部运行，哪些在 HKT 软件/云端运行？例如发热、饮水、运动能力、发情期及健康异常。**

记下：胶囊只负责测量和发送原始数据（体温、胃部活动、运动量、电量），不做任何判断。所有分析和提醒（发热、消化、饮水、发情、疫病、健康异常）都在软件平台上完成。

**2. 对于目前运行在 HKT 软件/云端的算法，它们是否也能在我们的自有服务器上运行？**

答案：可以 [x]　不可以 [ ]　需进一步讨论 [ ]

记下：在采用本地部署的前提下我们选择"可以"——全部分析功能（包括 AI）都随安装包部署在贵方服务器上，本地运行、不依赖我们的云；即使 AI 模块临时异常，基础的健康判断和告警功能照常工作。

**3. 如果需要使用 SDK 或算法包，它是否可以在无需与 HKT 服务器建立永久连接的情况下本地运行？**

答案：可以 [x]　不可以 [ ]　需要讨论 [ ]

记下：在本地部署方式下我们选择"可以"——软件和全部分析功能完全在本地运行，不需要与我们的服务器保持连接；授权一次导入即生效，仅续期时才需要导入新的授权文件。

**4. 本地安装的 HKT 软件是否需要定期在线许可证验证或从 HKT 进行远程激活？**

答案：是 [ ]　否 [x]　需进一步讨论 [ ]

记下：我们通过"离线授权"实现免联网验证——一张授权文件导入即激活，日常使用中不需要任何在线验证，我们也没有远程激活服务器。授权到期后软件自动降为基础功能、数据全部保留，续期后导入新授权立即恢复。

**5. 如果我们自行创建 UI 改进或新的业务功能，是否还能继续使用这些定制内容于 HKT 硬件上？**

答案：是 [x]　否 [ ]　需要讨论 [ ]

记下：在贵方自建系统通过我们的数据接口接入设备数据的前提下我们选择"是"——硬件和软件是分开的，贵方自己开发的界面和功能可以一直配合 HKT 硬件使用（数据格式与密钥支持见 B3/B4）。

**6. 如果 HKT 托管的服务不可用，哪些当前功能仍会在本地继续运行，哪些功能则会停止运行？请清晰列出。**

记下（以本地部署方式计）：

- **继续运行**：登录使用、看板与地图、电子围栏、告警中心、健康分析（发热/消化/发情/疫病/饮水）、AI 分析、历史数据与图表、数据导出；
