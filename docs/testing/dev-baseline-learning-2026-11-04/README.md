## 本轮抓到并修正的坑

1. **造态 SQL 硬编码 id**：昨日 fixture 的 id（85/163）被写死在 plant SQL，今日 fixture 重建拿到新 id（86/164）导致数据挂空、recalculate 报"数据不足"——已改查表式（`WHERE livestock_code=... AND dev_eui=...`），且发现评审 P2-6 的"无快照时响应合并为 insufficientData=true"确实容易误导排障（真因是缺快照不是数据不足）。
2. **会话注入历史谜团破案**：旧结论"localStorage 会话注入不闭环（恒 loggedOut）"的真根因 = SharedPreferences 网页端把字符串值 **JSON 编码**存储（`"zh"`/`"86"` 带引号）；裸值注入被解析为 null 且 restore 的 token==null 分支不清除键（与"键还在但弹回登录"现象完全吻合）。按插件格式（`JSON.stringify(value)`，user_info 双重编码）注入后 /ranch 直达。已写入 40-Pitfalls。
