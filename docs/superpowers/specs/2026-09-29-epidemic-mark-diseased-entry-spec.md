## 1. 背景与问题

疫病工作台（处置/记录/链路三视图）围绕"疑似源头病牛"展开，但当前存在**三层断层**，用户从概览点"疫病防控"只能看到空态：

| 层 | 现状 | 证据 |
|---|---|---|
| 数据层 | `contact_traces` **没有任何运行时生成器**，只有 V31 静态 demo 种子 | 全仓仅 V20/V21/V31/V20260926 四个迁移触碰该表；无任何 Service 写入 |
| 入口层 | `POST /epidemic/mark`（标记）与 `DELETE /epidemic/mark/{id}`（撤销）后端已实现、前端 repository/controller 已封装，**但零页面调用** | `markDiseased` 在 `lib/features` 无 UI 调用方 |
| 种子层 | V31 种子依赖 `livestock_code='SL-2024-048'`（farm 1），test 库无此编号牛 → **迁移"成功"但插入 0 行**（静默失效） | test `flyway_schema_history` V31 success=true，`contact_traces` 0 行 |

另有一个交互断层：概览疫病卡显示"7 日异常率 27.3% 已超警戒"（数据源=健康告警统计），点进去工作台却是空态（数据源=接触标记）——两者数据源不同且未衔接，本次设计一并给出最小衔接方案。

## 2. 目标与非目标

**目标**
1. 用户能把某只牛标记为"疑似患病源头"，标记后工作台立即可用（有源头、有接触网络、有处置队列）。
2. 能撤销标记（含撤销后自动取消该源头的活跃处置单——后端 `cancelActiveBySource` 已有）。
3. 接触数据有真实来源（不再依赖编号写死的 demo 种子）。
4. 概览警戒态与工作台空态不再互相矛盾。

**非目标**
- 不做 GPS 接触的常驻持续分析（接触关系随轨迹持续累积）——属后续优化，本设计用"标记时快照分析"降级覆盖；
- 不做病原学检测/兽医确诊流程；
- 不改概览疫病卡的计算口径（异常率仍来自健康告警）；
- NIX-246 Phase 3（牲畜详情页融合、病程卡）不在本设计内，仅预留挂载点。

## 3. 方案总览

四个部分，可独立裁决、分批实施：

```
┌─ A. 标记弹层（共享组件）─ MarkDiseasedSheet：选病种 → 确认
│      三个挂载入口：① 牲畜详情页 ② 疫病工作台空态 ③ 疫病类告警处置动作
├─ B. 数据层：标记时快照分析（markDiseased 改造，按需生成 contact_traces）
├─ C. 种子修复：疫情演练种子改为按现存牛群幂等生成
└─ D. 概览卡衔接：无标记源头时副文与点击落点调整
```

**依赖关系：A 依赖 B（没有接触数据，标记了工作台还是空）；C/D 独立。** 若只裁决 A 不做 B，标记功能等于装饰——建议 A+B 同批，C/D 可后置。

## 4. B：数据层——常驻分析器 + 标记时快照（双轨，已裁决）

### 4.1 双轨架构（裁决①：两者都要）

```
常驻轨（每日）                            即时轨（标记时）
─────────────────                        ─────────────────
ContactAnalysisScheduler                  markDiseased(...)
  每日 02:00 滚动重算近 72h 窗口            ① 即时跑一次同口径分析（覆盖最新轨迹）
  gps_logs → 牛对接触判定                    ② 标记该牛出向接触 markedAt/diseaseType
  → 写"接触池"（无疫情语义行）               ③ 工作台立即可用
  幂等：只 upsert 未 marked 的行
```

- **接触池**：常驻轨产出的行不带 `markedAt/diseaseType`，只是"哪些牛何时/多近/多久接触过"的事实积累——标记前即可支撑未来"接触网络预览"类功能。
- **即时轨兜底**：标记瞬间重算，保证刚发生（当天未跑到常驻分析）的接触不遗漏；两轨同口径（同一套接触判定与打分函数），结果可互相覆盖（未 marked 行）。

### 4.2 接触判定口径（两轨共用，做成配置项）

- 参数：`距离阈值 30m`、`单次最短 5min`、`窗口 72h`（与 V31 种子口径一致；markDiseased 请求体可带 `windowHours`，1–720 钳制）。
- 写入字段沿用现有表结构：`proximity_meters`（窗口内最小距离）、`contact_duration_minutes`（接触累计分钟）、`last_contact_at`、`risk_score/risk_level`（复用 `calculateTimeScore/DistanceScore/DurationScore`）。
- **幂等**：滚动重算只 upsert **未标记**的 from→to 行（已 marked 的行不动，保留疫情语义）；重复标记同一头牛 = 即时轨重算覆盖后再标记。
- **调度**：每日 02:00（配置 `health.contact.analysis-cron`），单牧场牛只几十头级、牛对千级、72h 轨迹量可控，**滚动重算优于增量游标**（GPS 迟到数据自然被下轮覆盖）。分析行数/耗时记结构化日志；窗口内无 GPS 数据则跳过并记日志（不算失败）。
- **边界**：72h 内无任何 GPS 轨迹 → 标记接口仍成功，响应附 `contactsGenerated: 0` 与提示码 `error.epidemicNoGpsWindow`；前端提示"近 72 小时无定位轨迹，接触网络为空，仅展示源头处置"。
- GPS 数据读取走 `gps_logs`（真实 TB 采集轨迹；datagen 仿真数据按 AGENTS 规则不作为验收依据）。

### 4.3 markDiseased 语义修正

现状只更新已存在 traces。改造后为：**即时分析（生成/刷新未标记行）→ 标记** 两段式；`unmarkDiseased` 保持现状（清 markedAt/diseaseType，Controller 已有的 `cancelActiveBySource` 清理处置单）。

## 5. A：标记入口与弹层交互

### 5.1 共享弹层 `MarkDiseasedSheet`（底部弹层，BottomSheet）

```
┌──────────────────────────────────────┐
│  标记疑似患病源头                      │
│  牛号 SL-2024-0063 · 当前栏位 3 号围栏   │
│──────────────────────────────────────│
│  病种（单选）                          │
│  ( ) 口蹄疫疑似   (•) 牛结核疑似        │
│  ( ) 布病疑似      ( ) 腹泻类疾病       │
│  ( ) 其他（下方输入框，选"其他"时出现）    │
│──────────────────────────────────────│
│  ⓘ 标记后将立即分析该牛近 72 小时的       │
│    接触轨迹，生成接触追踪与处置建议。      │
│                                      │
│  [ 取消 ]            [ 确认标记 ]       │
└──────────────────────────────────────┘
```

- 病种预设 5 项 + 自定义；预设与 V31 口径（"口蹄疫疑似"）一致，进 ARB 常量表（后端不做枚举校验，前端约束）。
- 提交 → `POST /farms/{farmId}/epidemic/mark`；成功后弹层关闭 + toast `已标记，接触分析完成（N 次接触）`（N 来自 B2 响应），并跳转 `/twin/epidemic?sourceLivestockId={id}`（直接看到该源头的工作台）。
- contactsGenerated=0 时 toast 改为无轨迹提示文案。
- **撤销**：牲畜详情页在"已标记"状态下显示"取消染病标记"次级按钮 → 二次确认弹窗（文案说明会同时取消该源头的未完成处置单）→ `DELETE /epidemic/mark/{id}`。

### 5.2 挂载入口（三处，全量可达性倒查）

| # | 位置 | 形态 | 触达路径 |
|---|---|---|---|
| ① | 牲畜详情页（`/twin/overview/:id`）健康信息区动作行 | "标记疑似患病" 主按钮（已标记态换为"取消染病标记"） | 牧场概览 → 围栏页 → 点牛只；或告警 → 查看牛只 |
| ② | 疫病工作台空态（本次刚加的 `_NoSourceState`） | 空态文案下加"去选择病牛"按钮 → 跳转围栏页牛只列表（选牛后进详情再标记，复用①；不直接嵌选择器，避免空态页过重） | 概览 → 疫病防控卡 → 空态 |
| ③ | 疫病类告警（`EPIDEMIC` 类型）详情/处置动作区 | "标记为源头" 动作（预填该告警关联牛，弹层只确认病种） | 告警中心 → 疫病告警 |

①为主入口（语义最正：对着这头牛操作）；③是快捷路径（告警本来就是"这头牛可能有问题"的信号）；②补全空态引导闭环（当前空态文案刻意不指向操作，裁决通过后改为指向①的可达路径）。

### 5.3 状态机（牛只维度）

```
未标记 ──标记──▶ 已标记(疑似源头) ──撤销──▶ 未标记
                    │
                    └─处置单流转（工作台内，已有逻辑不动）
```

- 多源头：多牛可同时处于"已标记"；工作台默认取 `markedAt` 最新（既有规则），概览提供多源头切换（既有）。
- 撤销 ≠ 删除接触历史：traces 行保留、`markedAt/diseaseType` 清空（现状语义，保持）。

### 5.4 权限与订阅门控

- **角色**：标记/撤销为管理动作，沿用工作台处置接口的 `hasManagerRole()` 口径（OWNER / B2B_ADMIN）；非管理角色隐藏按钮（不置灰）。
- **订阅**：工作台查看已是 `epidemic_alert` Premium+ 门控（spec §订阅）。标记入口对免费用户**可见但受限**：点击后走既有 `_LockedState` 升级引导（免费用户标记了也看不了工作台，直接隐藏会阻断感知；此点可选：隐藏 vs 引导，默认**引导**）。

## 6. C：种子修复（已裁决：迁移种子）

V31 静默 0 行的教训：**条件种子必须校验命中行数**。

- 新迁移 `V2026xxxx__epidemic_drill_seed.sql`：不再按编号找牛，改为按现存牛群**动态**构造演练数据——取 farm 1 现存牛中的若干头（如按 id 顺序前 4 头）构造演练源头 + 接触网络，幂等（存在演练行则跳过），`disease_type='疫情演练'` 明示非真实。
- 迁移内必须 `DO $$ ... RAISE EXCEPTION` 校验插入行数 > 0（fail-loudly，杜绝 V31 式静默失效）。
- 产物用于：test 环境演示工作台全功能（验收依赖）；`疫情演练` 字样保证与真实疫情数据可区分。

## 7. D：概览疫病卡衔接（最小改动）

无标记源头且异常率超警戒时，副文由"7 日异常率 X%，已超警戒线"改为两段式：`7 日异常率 X% · 未标记源头`，点击落点不变（进工作台看空态引导）。仅 ARB 文案与一行条件，不动卡片结构。

## 9. 验收标准

1. **端到端主旅程**：围栏页选牛 → 详情 → 标记（选病种）→ 自动跳工作台 → 三视图有数据（源头/接触/处置）；撤销后工作台回到空态、处置单被取消。
2. **B2 数据**：有真实 GPS 轨迹的牛标记后 `contact_traces` 非空且字段合理（距离/时长/风险分）；无轨迹牛标记成功且提示无 GPS。
3. **入口可达性倒查**（#25）：①②③三入口各走一遍；非 OWNER 角色不见按钮；免费用户点击走升级引导。
4. **种子**：test 部署后演练种子非空（若选种子方案），或脚本注入/清理往返干净（若选脚本方案）。
5. **回归**：工作台既有功能（窗口切换/多源头/处置流转）不回归；`flutter analyze`/`gen-l10n` 通过；中英不溢出。
6. **编译+部署+冒烟**：新端点行为 curl 冒烟；`main.dart.js` hash 对比。
