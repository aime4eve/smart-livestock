## 1. 背景与结论

评估（2026-09-18，test 库真实数据实证 + 6 篇学术论文）结论：

- **方案 A（设备 GPS + 网关坐标几何距离）为主**：`device_telemetry_logs` 每帧已落 `latitude/longitude/rssi/snr/gateway_id`，Haversine 直接可算；唯一缺口是网关坐标登记，由牧场主 App 自助标记解决。
- **方案 B（RSSI 反推距离）降级**：静态路损模型被实测证伪（-80dBm 桶内距离横跨 3m–2942m）；按论文（WiMOB 2019）验证的方法，改造为"用 GPS 有效帧作标定样本、逐网关动态维护 RSSI→距离分位数映射"，仅用于无 GPS 帧的档位推断，输出永远是档位+置信区间。
- **数据治理独立实现**（用户裁决）：GPS 坐标合法性校验是通用多设备治理框架的第一个规则集（NIX-220），后续接入瘤胃胶囊规则集；本需求的距离计算/标定样本以治理过滤为前置。

## 3. 数据与算法基础

- **帧级距离**：每帧距离 = 该帧设备 GPS → 该帧 gateway_id 所指网关的 Haversine 距离。同一设备相近时刻对不同网关各有一条距离记录（独立事实，非矛盾）。
- **派生视图**：设备最新 GPS 对所有已登记网关批量算距取 min = "当前位置最近网关"，用于覆盖区判断/地图着色，不替代逐帧记录。
- **距离曲线按网关分线**：gateway_id 切换时距离基准点变更，台阶属正常现象，禁止混单线。
- **动态映射（方案 B）**：每日任务用 GPS 有效帧作标定样本，逐网关建 RSSI→距离分位数表（非参数、时间加权）；回退顺序 = 映射表 → log-distance 粗档（仅 >100m 段可信）→ unknown。明确排除 ML 与 TDoA 路线。

## 4. 功能范围

### F1 网关位置自助标记（App"我的"）
- 入口在 `features/mine`；自动列出本牧场设备实际通联过的网关（"网关 183 · 最后通信 xx 前 · 标记状态"），不做手工输入 ID。
- 标记 = 一键当前定位（主）+ 地图拖动微调（辅，复用 NIX-213 围栏编辑交互）；精度圈展示，>50m 提示重标。
- 覆盖已有坐标时二次确认；标记人与标记时间随记录保存。

### F2 通讯距离计算与展示
- 设备详情按网关分组展示（"网关 24e124：最新 156m / 30 天中位 89m"）；曲线按网关分线。
- 帧级距离查询端点（farm-scoped）；无 GPS 帧走方案 B 档位推断。

### F3 链路质量分档与预警
- 设备×网关 30 天滑窗 RSSI/SNR → stable/weak/edge 三档。
- edge 档触发"信号弱/临近覆盖边缘"预警（9/15 失联前 RSSI -105 前兆实证），复用围栏告警去重+自动解除模式。

### F4 离群/盗失预警
- 口径：单头牛"对最近网关距离"持续超出牛群当日基线（群体中位数 + MAD 倍数）或超绝对阈值且持续 N 帧 → 离群事件。免围栏配置。
- 发情交叉：离群+发情评分高分 → 发情佐证（反哺 NIX-156）；离群+夜间+无发情信号 → 盗失/逃逸嫌疑升级。

### F5 归牧点名提醒
- 口径：傍晚设定时刻后，对最近网关距离仍超阈值（默认 200m，可配）的头数 → "还有 N 头未归"。

### F6 游走半径健康画像
- 个体"日均最大离网关距离/游走半径"入健康画像；"游走半径连续多日收缩"与步数/体温交叉作慢性病早期信号。需长基线，随画像模块节奏。

### F7 饮水访问辅助（协同项）
- 不单独立产品口径；NIX-157 水源围栏方案落地后，距离序列的周期性靠近作为辅助输入。

### F8 覆盖诊断与网关位置调整建议（2026-09-18 扩展，含三级能力）

面向实施/售后与牧场主的数据驱动选址决策支持，三级递进：

1. **覆盖质量热力图**：GPS 有效帧按位置铺图，**热力图呈现**（连续色带：信号好→信号差，无数据区留白），叠加牛群活动热点与网关/建议增补点位标记；覆盖空洞（有牲畜轨迹但无帧上传的片区）可见。底层统计按 100m 网格，呈现层为平滑热力。
2. **弱覆盖活动区识别**：底层按 100m 网格统计每格帧数与平均 RSSI；按"牲畜活动量 × 信号差"加权排序，输出弱覆盖活动区清单（如"东南牧区：日均 45 帧，平均 -108dBm"）。
3. **位置调整建议**（规则化输出，方向性口径）：
   - 弱覆盖帧集中于单一方向 → 建议网关天线抬高/向该方向迁移（附建议方向与量级）；
   - 弱区面积大且与主活动区分离 → 建议增补网关于片区中心（附建议坐标）；
   - 用路损模型做 what-if 预期改善（"边缘帧占比 35% → 12%"），**明确标注为方向性预测（百米级），受动物体损波动 ±10dB 限制，不承诺米级精度**。

数据依赖：P2 距离/覆盖数据积累 ≥30 天后建议才可用；此前显示"数据积累中（已积累 N 天）"。

**建议算法（2026-09-18 test 库试算验证）**：
1. 全局指标：近 30 天真实帧的档位占比（稳定/偏弱/边缘）；
2. 网格聚合：100m 网格统计帧数与平均 RSSI，活动量加权；
3. 方向判定：弱信号帧（<-95dBm）加权质心 vs 全体帧质心，偏移 <150m 视为无主导方向；
4. 成片判定：帧数 ≥15 且均值 <-95dBm 的相邻弱格 ≥3 个才算"成片弱区"；
5. 建议输出（仅当边缘占比 >10% 且方向集中或成片）：方向集中 → 迁移/抬天线（量级 = 弱区距离 × (1 − 10^(−ΔdB/(10n)))）；成片且独立 → 增补网关于弱区质心；路损模型 what-if 输出预期改善占比；
6. 兜底结论：不满足触发条件时输出"覆盖良好，无需调整"——**宁可不给建议，不给噪音建议**。
试算实证（test 库 38,567 帧：稳定 57.6%/偏弱 40.1%/边缘 2.3%，98.5% 帧集中在网关周边 5 格，弱信号质心与全体质心偏差 ~10m，无成片弱区）→ 当前数据下算法输出"覆盖良好，无需调整"，验证了判定规则不会制造假建议。

### F9 距离未知体验细节
- 无定位帧详情页显示"距网关：未知（无定位）+ 信号档位"，避免"没数据=系统坏了"客诉。

### F10 admin 网关对账视图（2026-09-18 纳入）
- platform_admin/b2b_admin 只读：全网关登记清单（gateway_id、坐标、标记人/时间/来源）、**未标记网关对账清单**（通联数据有 gateway_id 但登记表无坐标）、标记率统计。

### F11 数据治理模块（独立实现，NIX-220）
- 通用规则框架 `validate(frame) → pass/flag`，GPS 规则集一期（lat/lng 范围、(0,0) 无定位、gateway_id 缺失 flag）；过滤不删除（gps_logs 全量保留）；质量指标按设备/规则/天聚合；瘤胃胶囊规则集为后续接入方。
- 本需求所有距离/场景功能消费治理过滤后的数据。

|----|------|------|
| **P1** | F1 标记、F3 链路分档预警、通联网关发现端点、gateway_registry 表 | 无（纯已落库数据） |
| **P2** | F2 距离计算与展示、方案 B 动态映射、F10 admin 对账视图、F9 体验细节 | NIX-220 合法性校验落地 |
| **P3** | F4 离群/盗失（含发情交叉）、F5 归牧点名、F6 游走半径画像 | P2 距离数据积累 |
| **P4** | F8 覆盖诊断与位置调整建议（三级）、F7 饮水辅助（协同 NIX-157） | P2/P3 数据积累 ≥30 天 |

## 6. 验收标准

- 距离计算（留出法 80/20）：档位一致率 ≥80%；P50–P90 区间覆盖率 ≥90%。
- 覆盖提示：标记已有坐标网关必弹覆盖确认。
- 告警：edge 档预警与围栏告警同模式去重/自动解除；F4/F5 事件有独立去重窗口，不产生告警风暴。
- 权限：F10 仅 platform_admin/b2b_admin；标记入口 farm-scoped。
- i18n：全部用户可见文案走 AppLocalizations + MessageSource 双语。

## 7. 依赖与外部输入

- NIX-220（P2 前置）；NIX-156（F4 发情交叉对接）；NIX-157（F7 协同）。
- **待用户提供**：31号点与其余 13 颗真实网关的 gateway_id ↔ 点位对账（或由现场用户经 F1 自助标记）。
- 待原型评审：标记交互、网关发现列表形态、F4 阈值参数与告警文案、F5 归牧时刻配置位置。

## 8. 流程

feature 级三阶段确认：HTML 高保真原型（F1/F2/F10 页面）→ spec（设计令牌表+组件规格）→ plan → 编码。编码未经用户批准不得开始。
