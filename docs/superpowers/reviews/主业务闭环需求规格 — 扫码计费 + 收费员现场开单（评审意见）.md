## 一、阻断级问题（流程逻辑自相矛盾，必须先裁决）

### 1. EX-05「他车扫码停单」缺少在场判定，可能错误终止仍在场车辆的计费

这是全文最大的漏洞。看时间线：

- 车主 A 驶入占位，地磁 car_in 建单，但 A 一直未扫码；
- 车主 B 路过/误扫/或 A 还没走，扫了该车位码；
- 按 EX-05：「上一订单非终态 → 上一单以 B 的扫码时刻停计费结算 → 生成待缴费单」。

**问题是：A 的车物理上还停在车位里，订单却被停掉计费了。** 结果是：
- A 实际停车 N 小时，只计费到 B 扫码那一刻；
- A 还凭空背上一条欠费单，下次扫码被「一欠即拦」，投诉成本极高。

文档里 EX-14 说「若后到者实际在场，归 EX-01 冲突路径」，但 EX-05 没有设同样的前置——它只检查「活动订单是否非终态」，不检查**车位地磁当前是否空闲**。修复方向很明确：

> EX-05 仅在「地磁当前为空闲（即判定旧车已物理离开、只是 car_out 漏报）」时才允许他车扫码停旧单开新单；若地磁仍为占用，B 的扫码应走 EX-14/EX-01 冲突路径，不得停 A 的单。

这一条不补，幕 C 兜底 2 在真实场景下会变成客诉发生器。

### 2. 宽限窗（10min）< 免费段（15min），收费员会被派去免费段内的车「白跑单」

时序推演：10:00 车辆驶入，10:10 生成人工开单工单，收费员接单、赶路、拍照、提交、核实、打印——但**免费段到 10:15 才结束**。

- 若车主 10:12 驶离 → 订单 <15min 走 WAIVED，收费员白跑一趟；
- 若收费员 10:14 到场打印，收费单上「当前费用」是 ¥0.00——车主看到一张 0 元罚单夹雨刷上，体验极差且无法解释。

既然§4 明确「免费段内离场零费完结、不进催缴」，那在免费段未结束前就派收费员开单，业务上站不住。需要在评审时裁决（任选其一）：

| 方案                  | 说明                                                         |
| --------------------- | ------------------------------------------------------------ |
| A. 宽限窗 ≥ 免费段    | 默认宽限窗改为 15 分钟（或与免费段联动配置），免费段内不开单 |
| B. 工单分两级         | 超宽限窗先只生成「待观察」轻量提醒，免费段过后仍占用才转正式开单工单 |
| C. 维持现状但显式声明 | 接受白跑率，但收费单费用口径必须能显示「免费中，X 分钟后起算」 |

### 3. EX-01/EX-03/EX-14 都依赖「车主是否实际在场」，但全文没有定义判定手段

三处需要这个判定，且判定结果相反：

| 场景             | 需要的判定                   | 后果                            |
| ---------------- | ---------------------------- | ------------------------------- |
| EX-01 传感器哑火 | 车主**在场** → 生成冲突工单  | 不判定出来 → 哑火场景无法触发   |
| EX-03 扫错码     | 车主**不在场** → 仅 App 提示 | 误判在场 → 给扫错码的人生成工单 |
| EX-14 并发扫码   | 后到者**在场** → 走 EX-01    | 误判 → 错误工单                 |

平台端只有「车位空闲 + 无活动订单」这一条数据，**它无法区分**「A. 车主在场但地磁哑火」和「B. 车主扫错码」。可能的技术手段（App 上报 GPS 与车位坐标比对、蓝牙信标、Wi-Fi SSID、要求车主拍一张车位照）一个都没提。这不是实现细节，是**幕 A 冲突路径能否成立的前置**：建议补一节「在场判定机制」，否则 ML-A-2 和 ML-A-3 两条 AC 无法执行验收。

## 二、重要问题（口径缺口，建议评审时补齐）

### 4. 收费员工单（10min 触发）与 UNCONFIRMED 告警（15min 触发）双重通知、职责重叠

同一辆车，10 分钟时通知收费员去开单，15 分钟时又触发既有 `unconfirmed_occupancy` 告警通知运营台——**两路人马可能同时到场**。文档说「15min UNCONFIRMED 机制保留不动」，但没说明：

- 已有活动收费员工单的车辆，UNCONFIRMED 告警是否抑制？
- 收费员到场发现「订单已是 UNCONFIRMED」时按哪条流程走？

### 5. EX-19 回溯切分的触发条件不闭合

「误合并边界按离场候选时间戳回溯切分——由他车扫码停单/收费员到场核实触发」。但如果新进场车辆 **B 也不扫码**（很常见的逃逸车），且迟迟没人触发切分：

- A 的计费会一直算到切分点之前（费用追溯调整账单，财务侧要做贷记/补记）；
- B 在切分前是「无单」状态，地磁没给它建单，漏计费风险。

至少要补一条兜底：「合并窗内无订单占用的车辆，超宽限窗同样触发收费员工单，到场即触发切分」——但这又回到问题 2 的免费段矛盾，需要一并设计。

### 6. 催缴链对「匿名欠费车」失效

情形 3 的追缴锚点是收费员录入的车牌，但这类车的前提恰恰是**车主从未扫码、未留手机号**。而既有催缴链（短信/App 推送）需要触达渠道。结果是：

- 催缴通知发不出去，订单只能停在 PENDING_PAY → 被动等扫缴费码；
- 「一欠即拦」也拦不到（他不扫码）；
- 车牌在 `owner_vehicles` 里匹配上了才有救，匹配不上这条欠费实际无法回收。

建议显式写明「无联系方式欠费单直接进入 COLLECTING 人工追缴名单，并支持车牌绑定后补触达」，否则 EX-06 对幕 B 车辆是一句空话。

### 7. 收费单上的金额口径未定义

收费单打印「当前费用」，但打印后计费继续（车主可能几天后才扫缴费码）。需要裁决：扫码支付时按**支付时刻实时金额**还是**打印时刻金额**？涉及价格争议，必须写死，两条 AC（ML-B-4/ML-C-2）目前都验证不了。

### 8. 收费员到场前订单已终结，工单不会自动取消

EX-18 只覆盖「到场时车位已空闲」。还有一种更常见的情况：收费员还在路上，车主已扫码（EX-13 覆盖了）或已免费段内离场（**没有覆盖**）——工单应自动置 CANCELED_FALSE_ALARM 并通知收费员别跑了。当前只有超时未接单（EX-08）的升级，没有「目标订单消失」的监听。

## 三、次要问题（建议修订）

1. **「14 态状态机零改动」与「新增迁移仅一条」表述矛盾**——实际语义是「不修改既有迁移、只追加一条」，措辞改掉，否则实现团队会对 DDL 范围产生分歧。
2. **`field_citation` / `citation_ticket` 命名怪异**——像占位符或笔误（citation 是引用的意思），如果是内部代号建议换成 `field_work_order` / `collection_ticket` 之类，避免建表后再改。
3. **EX-15 离线扫码**说「扫码只是确认动作」——但如果离线确认带的是本地时间戳，回到线上可能已超 15min 确认线，需要定义以服务端收到时刻为准。
4. **缴费二维码 token 无过期/无次数策略**——收费单夹雨刷等于公开，建议明确「一单一 token、金额动态、可多次访问、支付后作废」。
5. **ML-X-1 权限矩阵**建议把「车主本人能否查看自己车位的现场工单证据照片」一并裁决（隐私）。
6. **EX-17 全局一欠即拦**建议加人工豁免通道（争议单、已申诉单不应拦截），否则运营会被投诉淹没。
7. **58mm 热敏纸打印二维码**——中文场地名+车位号+车牌+入场时间+金额+二维码+提示语，排版很可能塞不下，建议打印模板提前打样验证。
8. **免费段=0 的场地**：15min UNCONFIRMED 这条线是否仍固定 15 分钟？免费段可配、超时可配，两者关系建议写明。

## 四、建议补充的 AC

- ML-A-7：地磁仍占用时他车扫码 → 旧单不受影响，新车主走冲突路径（补问题 1）
- ML-B-8：免费段内（或宽限窗与免费段关系裁决后）不生成/自动取消开单工单（补问题 2）
- ML-B-9：工单存续期间目标订单已 WAIVED/PAID → 工单自动取消并推送收费员（补问题 8）
- ML-C-7：收费单扫码支付金额口径（实时 vs 打印时点）（补问题 7）
- ML-X-4：在场判定机制的准确性指标（GPS 半径、误判率上限）（补问题 3）

**总体结论**：三幕骨架和计费起点裁决（方案二）是自洽的，可以进入评审；但 **EX-05 的停单前置条件、宽限窗与免费段的时序、「车主在场」判定手段**这三处是逻辑硬缺口，建议在评审会上优先裁决——它们分别影响幕 C 兜底、幕 B 成本、幕 A 冲突路径的成立性。其余为口径细化，可在评审后随技术规格一并修订。
