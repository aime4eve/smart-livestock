# 智慧畜牧软件平台培训手册

> 版本：v1.0（2026-08-26）
> 适用对象：售前/商务人员、售后支持人员、测试与研发新人、参与方案交付的实施人员
> 定位：智慧畜牧解决方案中的软件平台分册。硬件细节见《GAT-100 牛羊追踪器培训手册》和《RBC-100 瘤胃胶囊培训手册》；本手册只讲平台如何接入设备数据并形成业务闭环。

---

## 1. 培训目标

完成本手册学习后，学员应能回答以下问题：

1. 软件平台在解决方案中承担什么职责，与 GAT-100、RBC-100、网关的边界是什么。
2. 一条设备上报数据如何变成地图位置、历史轨迹、围栏告警、健康趋势或 API 数据。
3. owner、worker、b2b_admin、platform_admin、api_consumer 分别看到和操作什么。
4. 牲畜档案、设备安装、围栏、告警、健康分析和订阅门控之间如何关联。
5. 平台哪些能力可以演示，哪些能力必须确认设备、数据量、订阅层级或 POC 后才能承诺。

---

## 2. 平台在解决方案中的定位

### 2.1 一句话定位

Smart Livestock Platform is the software layer that turns IoT device data into farm workflows: animal records, live map view, geofence alerts, health insights, subscription control, and API integration.

### 2.2 解决方案分层

```text
GAT-100 牛羊追踪器
  -> 位置、步数、三轴加速度、电量
RBC-100 瘤胃胶囊
  -> 瘤胃温度、胃动力、三轴加速度、电量
LoRaWAN 网关 / 网络服务器
  -> 设备数据接入与转发
Smart Livestock Platform
  -> 设备与牲畜绑定、地图、围栏、告警、健康分析、订阅、API
App / 管理端 / Open API
  -> 面向牧场主、牧工、集团管理员、平台管理员和第三方系统
```

### 2.3 平台价值

| 客户目标 | 平台作用 | 依赖条件 |
|---|---|---|
| 知道牲畜在哪里 | 地图展示、GPS 日志、历史轨迹、设备状态 | GAT-100 有效上报、网关覆盖、时间窗正确 |
| 减少越界和丢失损失 | 围栏配置、越界检测、告警状态流、处理记录 | 围栏配置正确、位置数据有效、告警通知链路确认 |
| 更早发现健康异常 | 体温、胃动力、活动量趋势和健康预警 | RBC-100/GAT-100 数据、牲畜绑定、订阅层级匹配 |
| 多牧场和多角色协作 | 租户、牧场、角色、Farm Scope、数据隔离 | 用户和牧场归属配置正确 |
| 集成企业系统 | Open API、API Key、scope、限流、调用统计 | API 范围、频率、安全和兼容策略确认 |
| 控制投资节奏 | 订阅层级、Feature Gate、配额、数据保留 | 商务政策和客户采购范围确认 |

## 3. 技术架构速查

### 3.1 系统组成

| 组件 | 技术 | 培训口径 |
|---|---|---|
| 移动端 | Flutter Web/App | 牧场主和牧工主要操作入口 |
| 后端 | Spring Boot 3.3 + Java 17 | 业务 API 与数据处理核心 |
| 数据库 | PostgreSQL 16 | 业务数据、设备数据、日志和订阅数据 |
| 缓存/限流 | Redis 7 | 缓存与 API Rate Limit |
| 事件 | RocketMQ 5.1 | 领域事件与上下文解耦 |
| 数据库迁移 | Flyway | 表结构演进和部署校验 |
| 地图瓦片 | tileserver-gl / MBTiles | 在线与离线地图能力 |
| API 认证 | JWT + API Key | App/Admin 使用 JWT，Open API 使用 API Key |

### 3.2 限界上下文

| 上下文 | 平台职责 | 关键能力 |
|---|---|---|
| Identity | 租户、用户、牧场、认证授权 | JWT 登录、多租户隔离、角色权限、API Key |
| Ranch | 牧场业务 | 牲畜、围栏、告警、地图、Dashboard |
| IoT | 设备与遥测 | 设备、License、安装、GPS 日志、遥测接入 |
| Health | 健康分析 | 温度、蠕动、发情、疫病、健康概览 |
| Commerce | 商业化 | 订阅、合同、分润、Feature Gate、配额 |
| Analytics/Portal | 开放能力 | API 用量、调用日志、趋势统计、开发者门户 |
| Shared | 横切能力 | 认证、错误响应、多租户上下文、限流、事件 |

### 3.3 数据闭环

```text
设备上报
  -> 网关/网络服务器转发
  -> 平台解析与入库
  -> 绑定牲畜档案
  -> 触发业务规则
     |-- 地图位置 / 历史轨迹
     |-- 围栏命中 / 越界告警
     |-- 温度、胃动力、活动趋势
     |-- 健康分析与预警
     |-- Open API 输出
  -> 用户确认、处理、归档或第三方系统消费
```

## 4. 核心功能培训

### 4.1 租户、牧场与权限

核心概念：

1. **Tenant**：客户组织，数据与订阅归属的基本单位。
2. **Farm**：牧场，业务数据和 farm-scoped API 的核心范围。
3. **User / Role**：用户与角色，决定可见页面和操作权限。
4. **Farm Scope**：限定请求只作用于当前牧场，防止跨牧场数据混淆。

角色速查：

| 角色 | 主要页面 | 可做的关键操作 |
|---|---|---|
| owner | App 全部业务页、后台、牧工管理、订阅 | 管理牲畜、围栏、设备、告警、订阅 |
| worker | 地图、告警、围栏、我的 | 查看地图和告警，确认告警 |
| b2b_admin | B 端控制台 | 管理旗下牧场、牧工、合同、对账 |
| platform_admin | 平台后台 | 管理租户、用户、合同、订阅服务、API 授权 |
| api_consumer | API / Portal | 使用 API Key 访问授权数据 |

培训重点：

- 牧场不是 owner 随意创建，而是由 b2b_admin 或 platform_admin 创建并分配。
- worker 只确认告警，不能处理和归档告警。
- 切换牧场后，farm-scoped 数据应自动刷新。
- 讲解权限时不要承诺矩阵之外的自定义角色。

### 4.2 牲畜数字档案

一头牲畜在平台中的档案应尽量包含：

| 数据 | 来源 | 用途 |
|---|---|---|
| 耳号 / 编码 / 品种 / 性别 | 人工录入或导入 | 识别个体、筛选和报表 |
| 设备绑定 | GAT-100 / RBC-100 安装记录 | 将遥测数据归属到个体 |
| 最新位置 | GPS 日志 | 地图展示和越界检测 |
| 历史轨迹 | GPS 日志时间序列 | 回溯放牧路径和行为范围 |
| 温度趋势 | RBC-100 | 发热和健康分析 |
| 胃动力趋势 | RBC-100 | 消化与健康分析 |
| 活动量趋势 | GAT-100 / RBC-100 | 行为、发情和异常辅助分析 |
| 告警记录 | 平台业务规则 | 处理闭环和责任追溯 |

关键提醒：

- 设备必须通过有效安装关系绑定到牲畜，否则平台只有设备数据，无法形成个体档案。
- GAT-100 主要提供位置与运动，不等于体内温度设备。
- RBC-100 提供瘤胃温度和胃动力，不承担 GPS 定位主职责。

### 4.3 地图、轨迹与离线能力

平台能力：

1. 地图概览：查看牧场、牲畜位置和设备状态。
2. 历史轨迹：按时间窗回放位置历史。
3. 离线瓦片：下载指定区域地图，支持弱网或无网场景查看。
4. 瓦片降级：在线瓦片、本地 MBTiles、公共地图源之间存在降级策略。

讲解边界：

- 地图位置是否及时，取决于设备上报周期、GPS 定位成功率、网关覆盖和网络状态。
- 离线地图不等于设备无网络仍能持续上报实时数据。
- 历史轨迹长度受数据保留策略和订阅层级影响。

### 4.4 电子围栏与告警

围栏状态逻辑：

| 状态 | 含义 |
|---|---|
| Safe | 点在围栏内且未进入缓冲区 |
| Approaching | 点接近边界，进入缓冲区 |
| Breach | 点在围栏外，触发越界 |

告警状态流：

```text
pending -> acknowledged -> handled -> archived
```

角色分工：

| 动作 | owner | worker |
|---|---|---|
| 确认告警 | Yes | Yes |
| 处理告警 | Yes | No |
| 归档告警 | Yes | No |

培训重点：

- 围栏是业务规则，不是地图上的视觉图形。
- 告警必须讲清“谁收到、谁确认、谁处理、何时归档”。
- 客户要求通知渠道、响应时限或 SLA 时，需商务与技术确认。

### 4.5 设备接入与数据解析

平台面对的设备数据主要包括：

| 设备 | 平台可接收的关键数据 | 业务用途 |
|---|---|---|
| GAT-100 | GPS 经纬度、步数、三轴加速度、电量、运行配置 | 位置、轨迹、活动量、设备状态 |
| RBC-100 | 瘤胃温度、胃动力、三轴加速度、电池电压/电量 | 健康趋势、发情与疾病辅助预警 |
| 网关 | 网关状态、网络转发 | 判断设备在线和覆盖风险 |

平台处理顺序：

1. 校验设备身份与频段/协议。
2. 按固件和 payload 协议解码。
3. 按设备安装关系关联牲畜。
4. 写入 GPS、温度、胃动力、活动等日志。
5. 触发围栏检测、健康分析或统计聚合。

必须牢记的硬件边界：

1. GAT-100 的防拆与温湿度是可选固件能力，默认不开启。
2. RBC-100 存在多种不兼容 payload 帧格式，接入前必须确认固件版本和帧头。
3. RBC-100 投服后不可回收，平台上线前必须完成投服前验活和编号登记。
4. 设备离线不一定是平台缺陷，可能是上报周期、电量、网关覆盖、频段或信号问题。

### 4.6 健康分析

平台可基于连续遥测数据输出：

| 分析方向 | 数据基础 | 培训表达 |
|---|---|---|
| 发热预警 | 瘤胃温度趋势 | 辅助发现体温异常个体 |
| 消化分析 | 胃动力差分趋势 | 辅助判断瘤胃活动变化 |
| 发情识别 | 温度、活动、行为趋势 | 提示可能发情个体，需人工确认 |
| 疫病防控 | 群体趋势、接触链路 | 辅助风险识别，不替代兽医诊断 |
| 行为分析 | 步数、加速度、位置变化 | 用于趋势和异常提示 |

禁止表述：

- AI 可以确诊疾病。
- 算法可完全替代人工观察或兽医诊断。
- 仿真数据效果等于生产效果。
- 未验证的准确率、召回率、误报率可直接承诺。

### 4.7 订阅、配额与 Feature Gate

平台商业控制：

| 机制 | 客户感知 | 平台行为 |
|---|---|---|
| Subscription Tier | 当前功能包和数据范围 | basic / standard / premium / enterprise |
| LOCK | 功能是否开放 | 低层级显示升级提示或限制入口 |
| LIMIT | 数量上限 | 围栏、牲畜等资源数量控制 |
| FILTER | 数据范围 | 历史数据保留天数裁剪 |
| Device License | 可用设备类型和数量 | 设备接入与安装限制 |
| API Rate Limit | 单位时间调用上限 | 超限返回限流错误 |

售前提醒：

- 报价前确认牲畜数量、设备数量、数据保留、API 调用量和支持等级。
- 代码中的价格结构只说明计费逻辑，不等于海外公开报价。
- API 用量计费具备计量基础，完整对外账单和免费额度策略仍需商务确认。

### 4.8 Open API 与开发者门户

能力：

1. API Key 认证。
2. scope 控制数据范围。
3. Rate Limit 控制调用频率。
4. 调用日志和日用量统计。
5. 趋势分析和使用概览。

常见数据对象：

- 牲畜。
- 围栏。
- 告警。
- 设备。
- GPS 日志。

讲解边界：

- Open API 与 App/Admin API 是不同路由和认证体系。
- API 兼容期、SLA、数据范围、调用频率和安全审查必须书面确认。
- 客户系统写入或二次分发数据时，需确认数据权责和安全责任。

## 5. 端到端业务流程

### 5.1 客户开通

```text
platform_admin 创建租户和初始用户
  -> b2b_admin 创建牧场并分配给 owner
  -> owner / 实施人员补齐牲畜档案
  -> 注册设备、License 和安装关系
  -> 配置围栏、告警、订阅和 API 权限
  -> worker 加入牧场并开始日常协作
```

### 5.2 GAT-100 定位到告警

```text
GAT-100 按周期上报 GPS / 步数 / 加速度
  -> 网关转发到平台
  -> 平台写入 GPS 日志并更新位置
  -> FenceBreachDetector 判断 Safe / Approaching / Breach
  -> 若越界，生成告警
  -> worker 确认，owner 处理并归档
```

### 5.3 RBC-100 数据到健康预警

```text
RBC-100 投服前验活
  -> 胶囊编号与牛耳号登记
  -> 投服进入瘤胃并转入工作模式
  -> 上报温度 / 胃动力 / 加速度
  -> 平台按牲畜归档并生成趋势
  -> 健康分析输出异常提示
  -> 牧场主或兽医复核处理
```

### 5.4 企业客户集成

```text
确认数据对象与调用频率
  -> 平台审批 API 授权和 scope
  -> 客户系统调用 Open API
  -> 平台记录调用日志与用量
  -> 客户系统展示或二次处理数据
```

### 10 分钟解决方案 Demo

| 时间 | 演示内容 | 讲解重点 |
|---|---|---|
| 1 分钟 | 客户目标复述 | 先确认客户关注丢失、健康、人工效率还是集成 |

| 2 分钟 | GAT-100 轨迹和围栏 | 位置如何变成业务规则和告警 |
| 2 分钟 | RBC-100 温度与胃动力 | 体内数据如何辅助健康判断 |
| 1 分钟 | 告警闭环 | worker 确认、owner 处理、归档留痕 |

Demo 红线：

1. 不把演示数据说成真实牧场生产效果。
2. 不承诺固定实时性和定位精度。
3. 不把健康预警说成诊断结论。
4. 不跳过设备、网络、安装、投服等前置条件。

## 7. 高频问题 Q&A

| 问题 | 标准答复 | 边界 |
|---|---|---|
| 平台能实时看到每头牛吗？ | 平台按设备上报周期展示最新位置和状态；及时性取决于设备配置、GPS 成功率和网络覆盖 | 不承诺 100% 实时 |
| 只有 GAT-100 能做健康分析吗？ | 可基于位置、步数和加速度做活动趋势；体温、胃动力等体内数据需要 RBC-100 | 不把运动分析说成生理诊断 |
| RBC-100 数据为什么平台看不到？ | 先查投服登记、激活状态、固件帧格式、网关覆盖、电池和绑定关系 | 不直接判平台缺陷 |
| 告警没有通知怎么办？ | 先确认告警是否生成、角色权限、通知渠道和客户配置 | 通知渠道和 SLA 需确认 |
| 历史数据能保留多久？ | 与订阅层级和合同配置相关 | 不承诺无限历史 |
| 能接入客户系统吗？ | Open API 可按 API Key 和 scope 授权访问部分数据 | 兼容期、频率、SLA、安全需确认 |
| 平台支持离线吗？ | App 支持离线地图、围栏和牲畜位置缓存等能力 | 不等于设备无网仍能持续上报 |
| AI 能判断疾病吗？ | AI 提供异常提示和趋势辅助，不替代兽医诊断 | 禁止诊断承诺 |

## 8. 培训练习

### 练习 1：模块复述

用 5 分钟画出“设备数据 -> 平台解析 -> 牲畜档案 -> 围栏/健康 -> 用户处理 -> API 输出”的闭环图。

### 练习 2：角色演示

分别用 owner 和 worker 登录，完成查看地图、确认告警、处理告警、归档告警，并说明权限差异。

### 练习 3：设备组合判断
