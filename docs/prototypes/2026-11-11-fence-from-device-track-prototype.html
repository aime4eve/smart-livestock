设计裁决要点（spec 阶段锁定依据）

入口新增围栏页"快速开始"区第 5 个入口（移动端在实地采集之下，卡片式）；Web 端入口不隐藏——本功能数据全部来自服务端，天然双端可用，区别于依赖本机 GPS 的"实地采集"（kIsWeb 隐藏）。
向导结构移动端三步向导（选设备 → 选时间 → 预览），复用 ImportWizardShell 外壳与步骤指示器语言；Web 宽屏合并为"左参数面板 + 右实时地图"单屏，参数改动后点「生成预览」刷新，免步骤切换。
设备列表多选 checkbox 卡片：设备名、绑定耳标、最近定位时间（超 24h 琥珀警示但仍可选）、近 30 天轨迹点数预估。底部常驻"已选 N 台 · 预估 M 点"，防止合并点爆炸。
时间范围快捷档（7/14/30 天）+ 自定义起止，硬上限 30 天：超限时输入框红框 + 提示 + 禁用下一步。提示文案引导用户选"最近一次完整放牧周期"。
预览三要素：① 凹包草图（虚线边表示"未确认"，载入表单后变实线）；② 半透明轨迹点叠加（--track-dot，35% 透明）让用户验证包络是否贴合实际活动区；③ 被剔除漫游点用琥珀色单独显示，让"95% 截断"可解释、可信任。暗色统计条（有效点/剔除数/顶点数/面积）沿用详情卡仪表盘语言。
失败态无轨迹 / 有效点<3 / 面积<25㎡ 共用同一空态版式：原因 + 清洗明细统计条 + 可操作建议（延长时间/增选设备/检查离线设备），操作按钮只有"返回调整条件"，不死胡同。
生成来源元数据预览页与围栏详情页均展示"生成来源"卡（设备、时间段、生成时间），随 POST /fences 落库 generation_metadata jsonb，支撑日后追溯与"重新生成"扩展。
新增令牌仅 7 个：--track-dot / --track-dot-opacity / --envelope-fill / --envelope-stroke / --envelope-stroke-dash / --chip-selected-bg / --stat-strip-bg / --step-indicator-inactive / --wizard-panel-width；其余全部继承 NIX-246 已锁定基线。

交互流与后端契约（供 spec 细化）

数据流选设备+时间 → 后端按 deviceIds 并发拉 gps_logs（幂等键 device_id+recorded_at）→ 服务端抽稀 ≤5,000 点传输 → 客户端管线：95% 距离分位数截断 → 精度过滤（阈值放宽至 30–50m，真机校准）→ MAD 清洗 → 凹包/凸包 → DP 抽稀 ≤100 顶点 → 预览 → 载入表单 → POST /fences（顶点 + generation_metadata）。
围栏保存完全复用现有 POST /fences：配额（FarmFenceUsageResolver）、乐观锁、告警判定零改动；仅请求体增加 generationMetadata 字段。
i18n全部文案走 AppLocalizations 双语；原型中文案即中文稿，英文稿在 spec 中成表。
权限与现有围栏创建一致（ranch owner/manager），canManage=false 时入口不显示。
性能约束单设备 30 天 ≈ 8,600 点（5 分钟采样），多选 4 台 ≈ 3.4 万点原始、抽稀后 ≤5,000 点传输（沿用 NIX-213 MAX_TRANSPORT_POINTS）；目标：典型数据 10 秒内出预览。
