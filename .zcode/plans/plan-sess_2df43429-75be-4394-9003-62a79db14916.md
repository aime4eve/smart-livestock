# NIX-191 实施计划（评审修订版）：签发工具独立部署 + 账号随证书诞生 + 合同自动关联

## 评审后并入的修正
1. 免登录窗口同时覆盖**登记（enrollment）+ 首张证书导入**（否则零账号状态拿不到安装 ID，第二处鸡生蛋）。
2. 免登录窗口内**只接受携带管理员字段的证书**（首张证书必须诞生管理员），防止"续费证书导致授权生效但无人管理、窗口永久敞开"。
3. **防复活回归**：到期证书按 EXPIRED 处理、REPLACED 证书拒绝导入，补专门测试用例。
4. 云端为签发工具建**专用机器账号**（仅合同列表+回写两权限），凭据配签发机 env。
5. 演示种子拆分精确清单：仅演示身份/演示数据进 db/demo；产品必需种子（功能开关、瓦片 worker key）留主 location；dev/test 的演示管理员由 db/demo 重建。
6. 签发机**双模式**：在线自动拉合同 + 离线手工录入合同号。
7. Python 生成 bcrypt 与 Java matches 的回程自动化测试；改密不强制下线旧 token（beta 接受并注明）；证书文件含手机号按敏感件对待。
8. 版本号以构建时 build.number 为准。

## 部署拓扑
- 我方内网签发机（用户提供）：license-issuer 独立 compose（SQLite 台账 + 私钥 0700 + 仅内网端口 + 可连通云端 API 或离线手工模式）。
- 我方云业务机（86 角色）：release 包 HOSTED；平台管理员=我方员工；客户仅租户管理员（建号即打强制改密标记）。
- 客户离线机（223 角色）：同一 release 包 ONPREM；零账号出厂 → 免登录登记+导入首张证书 → 管理员随证书诞生 → 首登强制改密。

## 任务清单（新分支 nix/191-admin-bootstrap，分卡提交）
1. 证书格式扩展：LicensePayload 增 adminPhone/adminPasswordHash 可选字段。
2. 用户表迁移：must_change_password 列；停用两个已知种子管理员。
3. 免登录窗口：登记与首张证书导入在"零管理员+待激活"状态免鉴权；窗口内只接受带管理员字段的证书；导入按手机号幂等创建 PLATFORM_ADMIN（bcrypt 直用，must_change=true）+ 审计。
4. 强制改密：PASSWORD_CHANGE_REQUIRED（双语）+ 拦截器白名单（登录/登出/改密/deployment-info/health/免登录窗口）；登录与 /me 返回标记；改密端点原密码+强度校验（≥10 位字母数字）+ 清标记；管理员自助改手机号（密码确认）。
5. 防复活回归：到期证书→EXPIRED、REPLACED 拒绝重导的测试用例；免登录窗口不得绕过。
6. 签发工具改造：管理员手机号（首装必填/续费可选）+ 14 位一次性密码生成（明文仅显示一次，bcrypt 入 payload）；合同台账页（云端拉取/离线手工双模式）、选合同自动带入档位期限、签发后回写 licenseId。
7. 云端合同挂钩：contracts.issued_license_id 列（Flyway）+ 回写端点 + 专用机器账号。
8. 签发工具独立部署：内网专用机 docker-compose（台账卷/私钥 0700/内网端口）+ README + 台账备份说明；目标机由用户提供。
9. 演示种子分离：db/demo 仅 dev/test 加载（精确清单：演示身份与演示数据；产品必需种子留主 location）；dev/test 演示管理员由 db/demo 重建。
10. Flutter：首登强制改密页 + 路由拦截 + arb 双语；ONPREM 隐藏「合同」入口。
11. 应急重置工具：服务器本地重置管理员密码（写审计、重置后 must_change=true）+ 运维指南。
12. 出包与双机演练（版本以构建为准）：223 全链路（装机→免登录登记→签发→免登录导入→管理员诞生→强制改密→解锁→续费验证不重置管理员）；86 升级回归（verify 13/13 + health 26/26）；安装/运维/playbook 指南更新（含交付 SOP、证书敏感件要求）。
